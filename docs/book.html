第一部分 Cosmos 介绍

1.1 世界基础模型是什么

2025 年 1 月 CES 上，NVIDIA 发布了 Cosmos 世界基础模型平台（World Foundation Model Platform），技术报告为 arXiv:2501.03575。它的定位一句话可以说清：物理 AI（机器人、自动驾驶、具身智能）需要先在数字世界里训练，而 Cosmos 就是那个"数字世界"的生成器。

NVIDIA 在报告里做了一个类比：LLM 之于语言，WFM（World Foundation Model，世界基础模型）之于物理世界。一个机器人需要两样"数字孪生"——它自己的策略模型（policy model），和它所处环境的世界模型（world model）。前者决定"做什么动作"，后者决定"世界会因此变成什么样"。Cosmos 提供的是后者：一个通用的、可微调的世界模型底座，让开发者不必从零训练自己的世界模型，只需在底座上做领域后训练。

与通用视频生成（Sora 类）最大的区别在于目标函数：Cosmos 生成的视频不是为了"好看"，而是为了物理一致性——重力、碰撞、遮挡、物体恒存性（object permanence）、光照变化都要符合物理规律，因为生成的每一帧都可能成为机器人的训练数据或测试环境。

规模事实：Cosmos 预训练使用了约 9000 万亿 token、约 2000 万小时视频数据，覆盖自动驾驶、机器人操作、工业场景、合成环境等。黄仁勋在 CES 主题演讲中称其使命为"让物理 AI 民主化，把通用机器人带给每一位开发者"。

1.2 平台总体架构

Cosmos 平台由四大组件构成，形成一条完整的数据-模型流水线：

组件作用关键数字
NeMo Curator 数据策展管线对海量原始视频做切分、转码、过滤、打标、嵌入Blackwell 平台上 14 天处理 2000 万小时视频（CPU 需 3.4 年），加速 89 倍
Cosmos Tokenizer 视觉分词器把图像/视频压缩成 token 供模型训练总压缩率较领先方案提升 8 倍，处理速度提升 12 倍
WFM 世界基础模型扩散与自回归两种架构的生成式世界模型预训练 9000 万亿 token，开放权重
NeMo Framework 训练框架后训练/微调与部署优化官方提供自动驾驶与机器人后训练示例
Guardrails 安全护栏Pre-guard 输入过滤 + Post-guard 输出审核关键词/Aegis 内容安全模型 + 人脸模糊 + 视频分类

1.3 数据策展管线 Curator

世界模型的预训练数据不是"下载来就用"。Cosmos 的数据管线对原始视频执行：

  1. 切分（split）：用镜头边界检测把长视频切成短片段，避免跨镜头的时间跳变污染时序建模；
  2. 转码（transcode）：统一到统一分辨率/帧率编码（如 H.264、720p、24fps）；
  3. 过滤（filter）：分辨率、清晰度/美观度、运动量（光流）三重阈值，剔除静态画面、低质片段；
  4. 打标（caption）：用 VLM 给每个片段生成描述文本，形成"视频-文本对"，这是生成模型的关键监督信号；
  5. 嵌入（embed）：计算 CLIP 风格语义向量入库，使后续可以用文本检索海量片段（如"雪夜公路""仓库拥堵""人手抓取杯子"）。

这套管线是后续一切的基础：无论是预训练、还是用检索出的领域片段做后训练，都依赖它把 PB 级原始视频变成"可检索、可训练"的数据集。

1.4 Cosmos Tokenizer

视频进入模型前必须先"token 化"。Cosmos Tokenizer 提供两种形态：

形态压缩配置最大帧数服务对象
连续（continuous）时间 8×、空间 8×8121 帧扩散 WFM（latent diffusion 输入）
离散（discrete）时间 8×、空间 16×16、词表 6553649 帧自回归 WFM（next-token prediction）

压缩率直接决定训练成本：压缩 8×8×8 意味着同样 GPU 预算下可以看 8 倍长的视频。Cosmos Tokenizer 相较当时的领先 tokenizer，总压缩率提升 8 倍、速度提升 12 倍，这也是 1X 等机器人公司直接采用它的原因。

1.5 世界基础模型 WFM

Cosmos WFM 有两条技术路线，都以 Transformer 为骨干：

自回归 WFM（Autoregressive）

  • Transformer decoder 结构，基于文本 + 过去帧预测下一个视觉 token；
  • 3D RoPE：对时间与空间维度分别编码位置信息；
  • 交叉注意力层注入文本条件，实现对世界内容的控制；
  • QK 归一化提升训练稳定性；
  • 渐进式预训练：先从 1 帧预测 17 帧 → 再到 34 帧 → 最终到 121 帧（约 5 万 token），后期加入高质量数据微调。

扩散 WFM（Diffusion）

  • 在连续 tokenizer 的 latent 空间做扩散去噪，支持 text2world / video2world 等任务；
  • 支持未来状态预测（forecasting），适合从当前观测推演"接下来世界会怎样"。
为什么两种都要？自回归路线天然适配"逐帧推演"的交互式世界模拟（策略评估、多步 roll-out）；扩散路线在单次生成的画质与可控性上更强（合成数据批量生产）。平台两条腿走路，让下游按需选型。

评测方面，报告在 3D 一致性、物理对齐（重力、碰撞等规律遵循）、相机位姿成功率等维度上，Cosmos WFM 相较同期基线模型表现更优——这正是"世界模型"区别于"娱乐视频模型"的核心指标。

1.6 后训练与领域定制

通用世界模型 ≠ 你的机器人所在的世界。Cosmos 的设计是：预训练底座开放权重 + 官方后训练示例，让开发者用自己的领域数据（机器人仓库实录、车载录像）做后训练，把"通才"变成"专才"。报告给出了两类官方示例：

  • 自动驾驶后训练：用车载多摄像头数据微调，使模型掌握特定车型视角下的驾驶世界推演；
  • 机器人后训练：用机器人第一视角操作视频微调，使模型生成"机械臂抓取-放置"等任务的未来帧，可用于策略评估与数据增广。

微调技术栈为 NVIDIA NeMo Framework（支持 LoRA 等参数高效方法），配合 Curator 检索出的领域片段，能以远小于预训练的数据量与算力完成定制。

1.7 安全护栏 Guardrails

生成式世界模型可能被诱导生成有害内容，也会把真实人脸生成出来。Cosmos 内置双层护栏：

  • Pre-guard（生成前）：关键词屏蔽 + Aegis 内容安全分类模型，对提示词做拦截；
  • Post-guard（生成后）：视频内容分类审核 + 人脸模糊（blur），防止输出包含可识别人脸的合成视频。

这套"输入过滤 → 生成 → 输出审核"的三段式结构，是任何自建世界模型平台（包括本书的 deephunch）都应当继承的安全基线。

1.8 模型家族演进（截至 2026 年）

发布一年后，Cosmos 家族已演进为三大产品线（均在 Hugging Face 开放权重，采用 NVIDIA 开放模型许可证）：

产品线定位2026 年最新版本要点
Cosmos Predict从文本/图像/视频提示生成未来世界状态Predict 2.5：统一 Text2World / Image2World / Video2World，基于 2 亿片段训练，支持最长 30 秒长尾场景生成、多视角输出、自定义相机布局、动作模拟等替代策略输出；用专有数据后训练后准确度可提升 10 倍
Cosmos TransferSim2Real：把仿真/3D 结构输入翻译成照片级真实视频Transfer 2.5：ControlNet 架构，输入分割图/深度图/边缘图/人体关键点/LiDAR/轨迹/HD Map/3D 包围盒等结构信号，输出空间精确对齐的逼真视频；支持 Image2Image 与 ImagePrompt；2.5-2B 轻量版物理对齐更强、长视频更稳定
Cosmos Reason物理 AI 推理 VLM：看见、理解、行动Reason 2：2B/8B 双规格，256K 长上下文，2D/3D 点定位与包围框、轨迹理解、推理过程可解释，登顶 Physical AI Bench 榜单

三者协同的典型用法：Omniverse/Isaac Sim 产出结构真值 → Cosmos Transfer 渲染成真实感视频 → Cosmos Predict 做未来推演与数据增广 → Cosmos Reason 给机器人策略提供感知推理。同期的 Isaac GR00T N1.6（人形机器人 VLA 基础模型）也集成了 Cosmos Reason。

1.9 产业生态

首发采用 Cosmos 的阵营横跨机器人与自动驾驶：机器人/具身智能侧有 1X、Agility、Figure AI、Agile Robots、Fourier（傅利叶）、Galbot、Hillbot、Skild AI、Neura Robotics、小鹏（XPENG）；自动驾驶侧有 Waabi、Wayve、Foretellix、Uber。典型用法：1X 用 Cosmos Tokenizer 构建 World Model Challenge 数据集；Agility 用 text/image/video-to-world 能力生成逼真场景替代昂贵实采；Foretellix 结合 Omniverse Sensor RTX 大规模生成测试场景。

本部分小结：Cosmos = 数据策展 + Tokenizer + 世界模型（自回归/扩散）+ 后训练框架 + 双层护栏的完整平台，而非单个模型。它把"世界模型"从少数大厂的专利变成开发者可下载、可微调的公共基础设施。
第二部分 deephunch 介绍和部署

2.1 项目定位

deephunch 是对 Cosmos 平台的架构级一比一复刻：以相同的组件划分、相同的流水线形态、相同的安全基线，构建一个可私有化部署、可接入任意推理后端的物理 AI 世界模型平台。默认内置 mock 后端，无 GPU 也能跑通"数据策展 → Tokenize → 世界生成 → 后训练 → 护栏"全流程；需要真实生成能力时，把后端指向你的推理服务（如本地部署的 Cosmos-Predict2）即可，上层编排代码一行不改。

2.2 模块映射与架构

Cosmos Tokenizerdh-tokenizer双配置：dh-tok-c8x8x8（连续·供扩散）与 dh-tok-d8x16x16（离散·供自回归），encode/decode 任务与压缩统计

技术栈：FastAPI + SQLite（纯标准库持久层，无编译扩展依赖）+ 线程池任务执行器 + 中文单页控制台，Docker 一键部署。

2.4 三步部署

方式一：裸机（最低配置即可）

git clone http://data.gitgg.com/deepsams/deephunch.git
cd deephunch
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8300

浏览器打开 http://<服务器IP>:8300，即进入中文控制台。七个页签对应平台七个模块，所有任务创建后由后台线程池异步执行，控制台每 5 秒自动刷新状态。

方式二：Docker

docker compose up -d --build    # 数据通过 volume 持久化在 dh-data 卷

初始化演示数据（可选）

python scripts/init_demo.py     # 预置示例数据集与 dh-predict/transfer/reason 模型工件

2.5 接入真实推理后端

平台默认 mock 后端（生成占位工件，跑通全流程）。接入真实世界模型只需两步：

  1. 部署任意 HTTP 推理服务（如本地部署的开源 Cosmos-Predict2，或自研扩散模型服务），暴露 POST /generate：入参 {model, mode, prompt, seed, duration_s}，返回 {video_url}；
  2. 设置环境变量并重启： 
    export DEEPHUNCH_WFM_BACKEND=remote
export DEEPHUNCH_WFM_REMOTE_URL=http://10.0.0.5:9000
export DEEPHUNCH_WFM_REMOTE_TOKEN=<可选>

生产化建议：任务队列换 Celery/Arq 并调度到 GPU 节点；产物改存 S3/OSS；Pre-guard 接内容安全模型；网关层接 GitLab OAuth 做 SSO。

第三部分 人形机器人（硬件 ODM）如何用 Cosmos 测试

3.1 ODM 的测试困境

人形机器人硬件 ODM（代工设计制造）处在产业链的尴尬位置：客户（品牌方/AI 公司）拥有算法，ODM 拥有硬件与产线，但算法测试高度依赖场景与数据——而 ODM 恰恰最缺：

  • 场景覆盖不足：机器人要在上千种光照、地面、物体布局下工作，实机逐项搭建场景成本极高；
  • 极端工况难复现：打滑、跌倒、遮挡、反光、拥挤人流等长尾场景，实机测试危险且难量化复现；
  • 客户验收缺少证据链：交付时说"底盘稳定性没问题"，客户要的是"在 X 类场景下 Y 万次测试通过"的可审计记录；
  • 回归测试周期长：改一颗关节电机参数，理论上要把全部场景重测一遍。

Cosmos 正好补上这一环：用世界模型在数字世界里无限复现与变奏真实场景，让 ODM 在交付前就能给出"场景级"的测试证据。

3.2 测试总体思路

核心公式：真实采集（少量）→ 结构化仿真（Isaac Sim/Omniverse）→ Cosmos Transfer 真实感渲染 → Cosmos Predict 场景变奏 → 大规模虚拟测试 → 实机抽检闭环。

  • 少量真实数据定标：在每个目标场景实采几十段视频，用 Curator 打标入库，作为"世界应该长什么样"的锚点；
  • 仿真提供结构真值：在 Isaac Sim 中搭数字孪生产线/家庭场景，输出分割图、深度图、关节轨迹等结构信号；
  • Cosmos Transfer 负责像不像：把仿真画面渲染成照片级视频，保证视觉分布接近真实（传感器在真实分布上测试才有意义）；
  • Cosmos Predict 负责多不多：以 text/image/video 条件批量生成场景变奏——换光照、换天气、换地面摩擦、换人群密度；
  • Cosmos Reason 负责判卷：用推理 VLM 自动判定测试视频中"机器人是否摔倒、是否抓取成功、是否符合任务要求"，替代人工看录像。

3.3 五步测试工作流

步骤 1：场景库建设

按客户交付场景建"场景卡片"：每个场景 = 结构描述（布局/物体/任务）+ 变奏维度（光照 × 天气 × 地面 × 干扰物 × 人群密度）+ 通过判据。用 deephunch 的 Curator 管线处理实采视频、打标入库，形成可检索的场景素材库。

步骤 2：虚拟场景量产

对每个场景卡片：Isaac Sim 出结构真值 → Transfer 渲染基础视频 → Predict 按变奏矩阵批量生成。一个场景卡片轻松裂变成数千段测试视频，全部带元数据（场景 ID、变奏参数、种子），可精确复现。

步骤 3：策略/控制器在环测试

  • SIL（软件在环）：把生成的视频流喂给客户的感知模型，测检测/分割/位姿精度在变奏下的衰减曲线；
  • HIL（硬件在环）：真实控制器/真机接入，虚拟世界作为"眼睛"——世界模型生成的未来帧作为传感器输入，验证控制回路响应；
  • World-model-in-the-loop：用后训练后的世界模型做策略评估（Cosmos 官方用途之一）：预测"如果执行这个动作，世界会怎样"，与真实 rollout 对比打分。

步骤 4：极端工况压力测试

在数字世界里免费做现实中不敢做的测试：湿滑地面行走、货架倒塌、人流冲撞、断电重启、关节过热降级……每种工况生成数百段视频，统计故障率。这些长尾场景恰恰是客户最关心、实机最难测的部分。

步骤 5：回归与验收证据链

硬件改版（换电机/换传感器/改结构）后，用同一批种子重新跑全部场景，自动对比新旧版本指标（成功率、摔倒率、任务完成时间）。Cosmos Reason 自动生成判定与解释，输出带审计字段（场景、参数、种子、判据、结论）的测试报告，作为 ODM 交付验收材料。

3.4 回归测试与验收

测试类型传统实机做法Cosmos/deephunch 做法收益
场景覆盖搭建 N 个实景场景卡片 × 变奏矩阵，量产数千段覆盖率提升一个数量级
长尾工况危险/难复现，多数放弃Predict 批量生成，参数可复现从"不测"到"全测"
回归测试改版后人工重测数周同种子全自动重跑，小时级改版→复测周期从周级到天级
验收证据现场演示 + 口头承诺带种子/判据的可审计报告交付争议大幅减少

3.5 落地清单

  1. 部署 deephunch（第二部分手册），数据集按"客户 × 场景卡片"组织；
  2. 每个目标场景实采 30–100 段视频定标，走 Curator 管线入库；
  3. Isaac Sim 搭 3–5 个核心场景数字孪生，导出结构真值（分割/深度/轨迹）；
  4. 接入 Transfer/Predict 推理后端（云端或本地 GPU 节点），开始场景量产；
  5. 用 Reason 建自动判卷规则库（摔倒判定、抓取成功、路径偏离等）；
  6. 把"虚拟测试报告"纳入 ODM 交付文档模板，形成差异化卖点。
本部分小结：对硬件 ODM 而言，Cosmos 的价值不是"又一个视频模型"，而是把测试从"搭实景"变成"写场景卡片 + 跑矩阵"——测试覆盖率、可复现性、交付证据链三个维度同时升级，这正是 ODM 从"代工制造"走向"代工验证"的入口。
第四部分 用 Cosmos 生成数据并卖出去

4.1 为什么数据能卖钱

物理 AI 公司最大的成本项之一是数据：Agility CTO 直言"数据的稀缺性和可变性是机器人环境学习的主要挑战"。一段高质量的机器人操作示教数据（遥操作采集）成本可达数十到数百元/条，且无法覆盖长尾。而 Cosmos 类世界模型可以以近乎零边际成本复制高质量场景并做系统性变奏。卖数据本质上是卖三样东西：

  1. 稀缺性：客户拿不到的场景（危险工况、产线内部、特殊地域）；
  2. 结构：不只是视频，还有对齐的标注——分割、深度、动作标签、语言指令；
  3. 合规放心：合成数据没有真人隐私、没有实拍版权问题（这正是 Post-guard 人脸模糊存在的意义）。

4.2 数据生产流水线

一条可复制的量产线（全部环节都对应 deephunch/Cosmos 的现成能力）：

  1. 种子采集：实采或仿真获得少量高保真种子场景（Isaac Sim 真值 + Transfer 渲染）；
  2. 变奏矩阵：Predict 按光照/天气/物体/视角矩阵批量生成，每个样本带完整元数据与随机种子；
  3. 自动标注：结构真值天然自带完美标注（无需人工标注），Reason 可补语义标签与指令文本；
  4. 质量过滤：用 Cosmos 管线同款指标（物理一致性、清晰度、运动量）自动筛掉劣质样本；
  5. 包装交付：按客户格式（LeRobot、OpenX 兼容、自定义 HDF5）打包，附数据卡（Data Card）说明分布与限制。

4.3 数据产品形态

产品内容典型买家
场景数据集（Dataset）特定领域带标注视频集（如"仓库人形操作 10 万条"，含分割/深度/动作标签）机器人算法公司、具身智能初创、高校实验室
生成 API（Data-as-a-Service）客户提交场景描述/结构输入，按条付费生成定制数据需要私有场景、不愿公开数据的客户
后训练服务用客户私有数据把 Cosmos 后训练成其领域专用世界模型（模型不卖，按项目收费）车厂、机器人品牌方

仿真中间件deephunch 平台私有化部署 + 场景库，卖 license + 年度维护大客户自建数据工厂

4.4 客户画像与定价

  • 机器人算法公司/初创：缺数据、缺钱、要快 → 卖标准数据集订阅 + API 充值；
  • 自动驾驶公司：要长尾场景（事故、恶劣天气）→ 卖定制生成，按场景复杂度计价；
  • 机器人品牌方/车厂：数据敏感不愿外流 → 卖私有化部署 + 后训练服务，项目制；
  • 高校/研究所：预算小、要引用规范 → 卖学术许可折扣版数据集。

4.5 渠道与销售打法

  1. 开源引流：deephunch 平台开源 + 发布几个免费小型示范数据集（Hugging Face/GitLab），建立技术信誉，把流量导给付费大集；
  2. 基准卡位：联合行业伙伴发布"XX 场景测试基准"（第三部分的场景包产品化），成为事实标准后向参赛者卖数据；
  3. ODM 联动：自家 ODM 交付时捆绑"虚拟测试报告 + 场景数据"，把测试能力变成对算法客户的数据销售入口；
  4. 生态合作：与仿真工具链（Isaac 生态）、标注公司、云厂商做渠道分成；
  5. 私有化大单：对数据敏感的头部客户走"平台 + 数据工厂共建"模式，客单价最高。

4.6 合规与风险

  • 许可链：Cosmos 采用 NVIDIA 开放模型许可证——用其生成的数据商用前需核对许可证条款（含 10 亿月活以下限制等），自研底座可彻底规避；deephunch 的 registry 模块应记录每个数据集的模型来源与许可；
  • 种子采集版权：实采视频需获得拍摄地/人物授权，或全部用仿真种子；
  • 隐私合规：坚持 Post-guard 人脸模糊；合成数据的优势就是"无真人"，不要破坏它；
  • 质量责任：数据卡中明确声明分布偏差（如"雨天样本基于仿真光照模型"），避免客户误用于安全关键决策；
  • 竞争壁垒：视频本身可被再生成，真正护城河是种子场景库 + 元数据体系 + 客户私有数据后训练的锁定效应——卖"持续更新的数据关系"，而非一次性文件。

4.7 90 天商业化路线

阶段目标关键动作

全书总结：Cosmos 证明了"世界模型平台化"的可行性；deephunch 把这套架构变成可私有部署的开源资产；对硬件 ODM，它是测试能力的代际升级；对数据生意，它是把"采集数据"变成"生产数据"的工厂。四件事连起来，就是一条从技术到营收的完整路径。
